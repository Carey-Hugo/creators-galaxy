### 为什么选择 Payment/Commerce 作为主方向

**理由一：这是 CGHub 创业的核心矛盾**

> "一个人干活容易，一群人协作分钱难"

CGHub 要做创客价值操作系统，最难的不是技术，是**贡献记录 → 价值确权 → 收益分配** 的闭环。如果这个问题没有好的解决方案，创客协作就停留在"微信群打卡"水平。

**理由二：市场存在真实缺口**

- Gitcoin 解决了公共物品资助，但没有个人贡献结算
- Safe 解决了多签钱包，但没有 AI Agent 的自动触发逻辑
- 现有平台（微信群、飞书）依赖人工对账，摩擦大、信任成本高

**理由三：AI 是这个方向的差异化关键**

```
传统方案：人工记录 → 人工审核 → 人工打款
        ↓ 问题：效率低、不透明、容易扯皮

AI×Web3 方案：
  AI 追踪贡献 → 智能合约确权 → 预设规则自动分配
        ↓ 优势：透明、可验证、自动执行
```

## 二、主方向深度分析：AI×Web3 Payment & Commerce

### 核心问题

**问题 1：谁记录贡献？**

- 现有方案：成员自己申报 → 人工审核（效率低、易造假）
- AI×Web3：AI Agent 全程追踪 → 链上存证（不可篡改）
- 技术依赖：链上活动日志（transactions、合约事件）

**问题 2：价值如何量化？**

- 现有方案：主观评估、投票、老大说了算
- AI×Web3：预设规则（智能合约）+ AI 辅助评估 + 社区确认
- 技术依赖：贡献评分算法、声誉系统

**问题 3：如何安全执行分配？**

- 现有方案：人工转账（中心化、依赖信任）
- AI×Web3：智能合约托管 → 触发条件满足 → 自动释放资金
- 技术依赖：Safe 多签、ERC-4337 账户抽象

**问题 4：AI Agent 的权限边界在哪？**

- Agent 能否自主发起支付？
- 谁为 Agent 的错误决策负责？
- 如何防止 Agent 被恶意利用？

### 关键项目参考

| 项目 | 给我们的启发 |
|------|------------|
| Safe (Gnosis Safe) | AI Agent 钱包的标准范式（Safe Modules） |
| Gitcoin Passport | 贡献者身份与声誉认证 |
| x402 (Paywall) | AI Agent 自主支付的最小可行协议 |
| ERC-4337 Account Abstraction | AI Agent 作为钱包所有者的技术基础 |

### 技术路线图（针对 CGHub）

```
Phase 1（可演示 MVP）：
  - 贡献记录：AI Agent 记录每次协作动作（链上事件）
  - 分配规则：Solidity 智能合约预设分配比例
  - 支付触发：满足条件后自动释放（Safe + ERC-4337）

Phase 2（完整系统）：
  - 声誉系统：Gitcoin Passport 风格
  - 动态分配：AI 辅助评估贡献权重
  - 多方托管：Safe 多签防止单点滥用
```

## 三、为什么 CGHub 必须解决这个问题

### Carey 的创业初心

> "创客经济最大的问题不是能力，而是价值不被记录"

一个创客做了大量前期探索、贡献了关键想法，但最后项目成了别人的。
原因：没有工具记录贡献，没有机制确权价值。

### CGHub 的答案

```
CGHub 的三层架构：

┌────────────────────────────────────────────┐
│  身份层：创客主页（Lens + 个人作品集）      │
│           → 你是谁，能做什么               │
├────────────────────────────────────────────┤
│  协作层：项目合作 + AI 贡献追踪             │
│           → 你做了什么，记录即确权          │
├────────────────────────────────────────────┤
│  价值层：智能合约分配 + 链上收益记录         │
│           → 贡献 → 价值 → 分配（自动）      │
└────────────────────────────────────────────┘

AI Agent 贯穿全程：
  - 记录贡献（自动追踪）
  - 评估价值（辅助判断）
  - 执行分配（智能合约）
```

## 四、兼固方向：Governance（治理与协作）

### 为什么 Governance 是必须兼顾的方向

Payment/Commerce 和 Governance 是**一体两面**，不是二选一：

```
Payment（收益分配）←→ Governance（治理协作）

Payment 回答：分什么（贡献 → 价值 → 收益）
Governance 回答：谁来定规则、谁来决策、如何分工

没有 Governance：
  - "贡献权重谁定？" → 没人定
  - "分配比例谁批？" → 没人批
  - "争议谁裁决？" → 扯皮

没有 Payment：
  - Governance 的决策无法执行
  - 社区协作没有利益闭环

CGHub 的完整闭环：
  Governance（决策层）→ Payment（执行层）→ 共同构成合伙人协作系统
```

### CGHub 的 Governance 核心问题

```
问题 1：规则谁来定？
  - 合伙人协议如何起草？
  - 贡献定义谁说了算？
  - 分配比例如何调整？

问题 2：分歧如何裁决？
  - 贡献权重争议
  - 收益分配争议
  - 角色权限争议

问题 3：AI 在治理中扮演什么角色？
  - AI 能否发起提案？
  - AI 能否参与投票？
  - AI 的投票权重是多少？
```

### Governance 的技术参考

| 项目 | 借鉴什么 |
|------|---------|
| Nouns DAO | 每日拍卖 + 提案 + 投票的治理循环 |
| Compound Governor | 链上治理合约标准（Governor Bravo） |
| Safe Snap | 预测性治理（提案通过后自动执行） |
| Snapshot | 链下投票 + 链上执行分离（低成本治理） |

### 战略优先级

| 方向 | 优先级 | 说明 |
|------|--------|------|
| Payment/Commerce | 🔴 主线 | CGHub 核心价值闭环，今天必须回答的问题 |
| Governance | 🟡 兼固 | Payment 的决策层支撑，是 CGHub 合伙人系统的另一半 |

**W2 的策略：Payment 为主线深挖，Governance 同步研究，两个方向不割裂。**

## 五、结论与下一步

**W2-01 结论：**

1. **AI×Web3 Payment/Commerce 是 CGHub 的核心主线**
2. **Governance 是必须兼顾的支撑方向**：Payment 没有 Governance 支撑，分配规则没人定
3. **两者共同构成 CGHub 合伙人协作系统的完整闭环**
4. 技术基础：Safe + ERC-4337 + 智能合约分配 + DAO 治理机制
