## 一、MVP目标：演示什么

### 核心演示：贡献到收益的完整闭环

```
步骤1：用户创建一个项目，设置分配规则（智能合约）
步骤2：项目成员提交贡献
步骤3：CGHub Agent记录贡献（自动）
步骤4：x402协议生成可验证的贡献证明
步骤5：智能合约按规则自动分配收益（钱包到账）
```

**这是"贡献记录 → Agent处理 → x402证明 → 链上分配"的最小闭环演示。**

不要求功能完整，不要求界面精美——**要求闭环跑通，能截图/录屏证明**。

## 二、组织形态：蜂巢思维 + 篝火模式

### 核心理念

**蜂巢思维（Hive Mind）**：信息完全透明，目标高度一致，决策分布式。每个人都是实际执行者，不是传话筒。

**篝火模式（Bonfire）**：小团队围绕问题自然聚集，问题解决后自动解散，流向下一个问题。不是「分配任务→等待交付」，是「围火协作→燃完散开」。

### 三个人怎么围火

| 传统角色 | 篝火角色 | 围火职责 |
|---------|---------|---------|
| Solidity开发 | 链侧火堆 | 合约部署、链上逻辑、x402接口 |
| 前端开发 | 端侧火堆 | 贡献记录界面、收益展示、用户操作 |
| Agent开发 | 记录火堆 | 贡献记录、证明生成、调度逻辑 |
| 统筹（你） | 掌火人 | 方向判断、资源协调、紧急裁决 |

**关键区别**：你不是老板，你是「最后一个拍板的人」。日常决策分布式，遇到争议你判断。

### 信息透明三板斧

1. **代码**：GitHub共享仓库，任何人任何时候可以提交，无需审批
2. **文档**：Obsidian共享库，实时更新，不需要汇报进度
3. **决策**：Telegram群 + Hermes记录，有分歧群里吵清楚，结论透明留存

## 三、分阶段计划（篝火节奏）

### 第一堆火：Day 1-3（搭框架，跑闭环）

**目标**：三个人同时围绕「最小闭环跑通」围火

- Solidity：合约骨架 + 部署到测试网
- 前端：项目初始化 + 核心页面框架
- Agent：贡献记录逻辑 + x402集成草稿
- **全程透明**：有问题随时拉人讨论，不存在「等我问一下」

**交付**：三个模块都能独立运行，为集成做准备

---

### 散开燃烧：Day 4-7（各自推进）

**篝火模式**：各自独立开发和调试，Telegram群同步进度（不是汇报，是透明共享）

- 有卡点 → Telegram拉临时篝火 → 问题解决后继续独立燃烧
- 遇到分歧 → 群里吵清楚 → Hermes记结论 → 继续

**交付**：各自模块基本完成，开始集成准备

---

### 第二堆火：Day 8-10（集成与调优）

**目标**：三个人集中解决集成问题

- 前端对接合约（连接钱包、调用分配函数）
- Agent串联测试：贡献→证明→合约→钱包
- 全流程跑通测试

**交付**：闭环稳定，能演示

---

### 第三堆火：Day 11-14（Demo录制 + 收尾）

- 封面图 + 文案（可并行）
- Demo录屏（整体介绍 + 核心流程）
- README + 操作指南
- QA文档准备

**交付**：可发布的演示包 + 评审视频
